# MediCode · 员工域低代码化设计方案（对齐 NocoBase）

> 版本 v1.1 · 2026-09-14（实现完成）
> 范围：在不破坏既有「登录/认证/患者域/AI 诊断/插件/工作流」功能的前提下，把**员工端**改造成 NocoBase 式「元数据驱动、可配置、可编排」的低代码系统。
> 一句话：**管理员能在界面上动态建集合（真建表）→ 自动获得 CRUD 页面 → 按角色配数据权限 → 挂业务工作流**；医生/员工侧使用同一引擎渲染出的页面，无需再写死代码。

### 2.1 命名与表设计
- 动态集合元数据存 `dyn_collections`（`name` 唯一，如 `staff_leave`；`fields_json` 存字段配置）。
- 物理表名 `dyn_<name>`，建在 **employee.db**；仅 `[a-z][a-z0-9_]{1,49}` 合法，杜绝 SQL 注入。
- 每张动态表固定带隐藏列：`id`(PK)、`_owner_id`、`_owner_dept`、`created_at`、`updated_at`，用于行级权限与审计。
- 字段类型（最小集）：`text/textarea/number/select/date/datetime/boolean`。字段配置含 `required/options/unique/searchable/table_visible/readonly`。

## 3. ACL 规则（数据权限）

规则四元组：`(角色, 集合, 动作集合, 可见范围)`。
- 动作：`view/create/update/delete`。
- 范围：`all`（全部行）/ `dept`（`_owner_dept == 当前用户科室`，体现「按科室可见」）/ `self`（`_owner_id == 当前用户`）。
- 默认兜底：`admin → 全集合全动作 all`；其他角色无规则则不可见。
- 引擎在列表/详情/改/删统一套用：无 `view` 则列表返回空并 403 于详情；无对应动作则 403；改/删先校验目标行是否落在自己可见范围。

## 4. 业务工作流（通用流程引擎）

- 定义 `wf_defs`：`key`、`trigger_collection`、`status_field`、`nodes_json`（节点：`{name, assign_type: role|superior, assign_value, action}`）。
- 实例 `wf_instances`：记录当前节点、`assignee_ids`、状态、历史、关联的动态行。
- 触发：对集合新建一行时，若命中 `trigger_collection` 且有可用流程 → 自动起流程实例、把 `status_field` 置为「审批中」。
- 流转：审批人 = 「当前节点 assign_type」解析出的用户集（如 `superior` → 创建者的 `superior_id`；`role` → 该角色的所有用户）；任一审批人调用 approve/reject 即流转/终态，并**回写动态行状态**。

请假审批示例：`staff_leave` 集合（申请人/类型/起止/天数/事由/状态）→ 员工提交 → 状态“审批中” → 上级（无则管理员）审批 → “已批准 / 已驳回”。

## 5. 四个开箱场景（种子）

| 菜单 | 集合名 | 字段要点 | ACL 示例 | 流程 |
|---|---|---|---|---|
| 排班管理 | `staff_schedule` | 科室(select)/日期/时段/值班人(text)/备注 | admin 全量增改删，医生/药剂/运维仅 view all | - |
| 请假审批 | `staff_leave` | 类型/起止日期/天数/事由/状态 | 本人 create self；admin update all；全员 view dept+self | ✔ |
| 公告 | `announcement` | 标题/正文/发布人/置顶 | 全员 view；admin create/delete | - |
| 科室组织 | `department` | 名称/上级(parent)/负责人 | admin 全量；其余 view all | - |

> 以上仅演示。管理员可在「数据源」里任意新增集合，页面即自动可用。

### 8.1 系统集合
动态集合除自建 `dyn_<name>` 外，新增 **系统集合**（`options.system=true`），把既有物理表接入同一套低代码能力：
- `medical_records`（患者库就诊记录）作为首个系统集合：非管理员**只读+搜索**，管理员可改/删；新建仍走原临床页面。
- 患者/医生显示名通过字段元数据 `ref`（table/label）自动解析（`{field}__label`）。
- 实现：`services/system_coll.py`（PRAGMA 白名单 + 原生 SQL，规避跨库外键反射），`api/dyn` 按 `options.system` 分发，不破坏既有 `dyn_*` 逻辑。
- 侧边栏「就诊记录」→ `/lcp/medical-records`。

### 8.2 侧边栏精简（按角色）
新结构：**控制台 / 诊疗 / 员工 / 知识库 / 管理(仅管理员)**。
- 诊疗：患者管理、患者档案、就诊记录(动态)、AI 诊断、医生工作台。
- 员工：院内公告、排班表、请假审批、科室组织、消息。
- 管理（仅 admin）：用户管理、审核中心、低代码工作台、技能/MCP/会话/Token 收敛于此。
- 移除侧栏“设置”；个人设置保留在右上角头像菜单。
