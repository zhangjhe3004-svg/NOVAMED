# 附近互传与连接机制（3D 全息版）

> 更新时间：2026-10-11。本文档描述员工端「附近互传」模块的 3D 视觉、连接申请/审批/断开机制与相关 API。

## 一、3D 全息视觉（HolographicScene3D）

- 组件：`frontend/src/components/HolographicScene3D.tsx`（原生 Three.js + OrbitControls）
- 中心 = 本机大号全息球（半径 24，520 核心粒子 + 220 卫星粒子），同事 = 环绕小球（半径 13，190 + 90 粒子），3D 椭圆轨道 + z 轴深度错开
- 每个球体由 5 层构成：内核心光晕（AdditiveBlending）、icosahedron 线框、球面点云（Fibonacci 分布）、卫星球壳点云（独立反转旋转）、倾斜光环带（TorusGeometry）
- 连接状态配色：已连接 = 全息青 `#00F0FF`/克莱因蓝 `#002FA7`；未连接 = 灰蓝 `#7ca8cc`/`#2a3c66`（动态 applyColor，无需重建场景）
- 交互：**左键拖拽旋转视角、滚轮缩放（40~360）、右键/中键平移**
- 场景通过 `project()` 把节点世界坐标投影为屏幕坐标，经 `onProject` 回调驱动 DOM overlay（中心 drop zone、节点交互圆、节点名、名片）实时跟随
- 搜索定位：`focusNodeId` 变化时相机 `controls.target` 平滑 lerp 对准目标节点
- 性能约定：节点/连线数据变化走 `rebuildRef` 就地重建（保留相机视角），仅 width/height 变化才整体重建

## 二、连接机制（互传授权）

### 规则

1. 互传必须同时满足：**对方在责任链内**（向上所有上级 + 向下所有下级）且 **已建立连接（accepted）**
2. 连接申请权限规则：
   - 申请方权限 **低于** 对方（auth_level 数值小）→ `pending`，需对方审批
   - 同级或申请方权限更高 → 自动 `accepted`
3. 每对用户只保留一条连接记录：已有 accepted 直接复用；pending/rejected 复用旧记录更新方向
4. 断开：双方任一方均可 `DELETE /connect/{peer_id}`；待审批（pending）申请也可撤回；断开后对方收到站内通知
5. 审批动作（通过/拒绝）与断开均写 `notifications` 站内通知

### 数据模型（employee.db.nearby_connections）

| 字段 | 说明 |
|---|---|
| requester_id / target_id | 申请方（低权限）/ 审批方（高权限） |
| status | pending 待审批 / accepted 已连接 / rejected 已拒绝 |
| note | 申请备注 |
| created_at / updated_at | 时间戳 |

### API 一览（/api/nearby）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/connections` | 已连接对方 id 列表 + 待我审批（incoming_pending）+ 我发出的申请状态（outgoing） |
| POST | `/connect/request` | 发起申请 `{target_id, note}`，返回 status（accepted/pending） |
| POST | `/connect/{id}/respond` | 审批方通过/拒绝 `{accept}` |
| DELETE | `/connect/{peer_id}` | 断开连接 / 撤回申请 |
| POST | `/transfer` `/transfer-file` | 互传（文本/记录/任意格式文件），未连接返回 403 |

## 三、前端交互（NearbyShare.tsx）

1. **搜索定位 + 申请连接**：图框外搜索栏输入姓名/用户名/科室 → 匹配员工按钮 → 点击「定位并连接」相机飞向其节点 + 自动发起连接申请（自动通过时直接打开传输弹窗）
2. **拖拽申请/断开**：未连接节点拖入中心圈 = 发起申请；已连接节点再次拖入 = 断开
3. **审批面板**：画布顶部展示收到的待审批申请（对方姓名/级别/备注），可「通过/拒绝」
4. **节点状态标签**：已连接（青）/ 申请中（琥珀）/ 被拒绝（红）/ 待连接（灰）
5. **团队弹窗断开**：点击节点查看其负责人员，已连接时弹窗内提供「断开连接」按钮
6. **传输门禁**：传输弹窗打开前校验已连接（后端二次强校验）

## 四、典型流程

```
低权限员工 A（L8）                     高权限员工 B（L9）
      │  搜索 admin05 → 定位并连接            │
      │──────── POST /connect/request ───────▶│  收到申请（画布顶部审批面板 + 站内通知）
      │        status = pending               │
      │                                       │── 点击「通过」──▶ POST /connect/{id}/respond
      │◀─── 站内通知「连接申请已通过」──────────│        status = accepted
      │════════════ 互传文件（双端可发）═══════▶│
      │  任一方拖拽断开 / 弹窗断开              │
      │──────── DELETE /connect/{peer} ──────▶│  收到「互传连接已断开」通知
```
