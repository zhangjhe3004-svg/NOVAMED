## 一、项目概述

### 1.1 项目名称
**MediCode全域智慧医疗系统**（暂定名，可修改）

### 1.2 一句话描述
一个可在普通电脑、专用边缘设备上运行的智能医疗辅助系统，能存储患者数据、分析病史、通过 AI 辅助医生做出诊断判断。

### 1.3 项目目标
构建一套基于边缘计算平台的智慧医疗系统，实现：
- **本地化运行**：部署在医院本地边缘设备，不依赖网络也能工作。
- **AI 辅助诊断**：通过 AI 模型分析患者症状和历史数据，辅助医生判断（仅供参考）。
- **数据安全保障**：敏感医疗数据本地处理，不上传云端。
- **多设备支持**：Windows / Mac / Linux。

### 1.4 核心痛点
| 痛点 | 说明 |
|------|------|
| 数据孤岛 | 患者身份、病历、影像等数据分散在不同系统 |
| 流程繁琐 | 挂号、初诊、AI 辅助、医生复核环节多、等待长 |
| 网络依赖 | 医院内部网络不稳，纯云端方案有瘫痪风险 |
| 隐私合规 | 医疗数据敏感，须符合最小化与隐私要求 |
| 胶片效率 | 纸质报告与医疗胶片获取耗时、管理混乱 |

## 五、技术栈

| 类别 | 选择 | 一句话 |
|------|------|-------|
| 后端 | **Python (FastAPI)** | AI 领域最主流，医疗 AI 库最全 |
| 前端 | **React + TypeScript** | 生态最成熟，组件库丰富 |
| UI | **Ant Design 5** + **Material 3** | 专业医疗风格 |
| 数据库 | **SQLite(开发) / PostgreSQL(生产)** | 结构化存储 |
| 向量搜索 | **FAISS + NumPy** | 语义相似病例匹配 |
| 非结构化 | **MongoDB（可选）** | 训练数据/知识文档/行为日志 |
| 运行 | **Docker** | 一次打包到处运行 |
| AI | **混合模式** | 规则引擎 + 向量搜索 + 可选云端 API |

**为什么这样选**：AI 库最全（PyTorch/ONNX/OpenCV）、开发快、社区多（后端）；生态最成熟、类型安全（前端）；结构存储、ACID、开源免费（数据库）；一次打包跨平台（Docker）；离线可用 + 效果优秀 + 隐私安全 + 灵活切换（AI 混合）。

## 六、AI 防幻觉体系（核心增强）

### 6.1 配置源 `config/agent_config.json`
以 `ai.json` 的「验证专家」骨架为基底，由 `backend/app/core/agent_config.py` 加载（缓存 + 容错）。当前配置文件已归入 `config/` 目录。关键结构：

```jsonc
{
  "agent_configuration": {
    "system_identity":   { "role": "严谨的医疗验证型AI诊断助手", "objective", "tone", "medical_context" },
    "system_prompt":     "含 CoT/ToT/引用验证/撤回兜底/医生确认门控",
    "generation_parameters": { "temperature": 0.2, "top_p": 0.9, "repetition_penalty": 1.2,
                               "min_p": 0.05, "num_ctx": 16384, "do_sample": true, "seed": 42, "max_tokens": 4096 },
    "scenario_parameter_profiles": { "default", "exploration_phase(0.6)", "verification_phase(0.1)" },
    "prompt_engineering_strategies": { "chain_of_thought", "tree_of_thoughts", "self_consistency",
                                       "react_prompting", "backtracking", "role_playing", "few_shot_examples" },
    "anti_hallucination_mechanisms": { "citation_verification", "direct_quotation_required",
                                       "evidence_tiering", "long_document_protocol",
                                       "best_of_n_verification", "claim_retraction",
                                       "unknown_fallback", "doctor_confirmation_gate" },
    "task_workflow": { "step_1_task_decomposition ... step_7_confidence_and_risk_label" },
    "workflow_settings": { "best_of_n_samples": 5, "enable_cot": true, "strict_fact_checking": true },
    "diagnosis_workflow": { "pipeline": [ {key,name,group,order,enabled,desc} x5 ] }
  }
}
```

### 6.2 参数与机制
- **低温参数**：temperature 0.2（验证 0.1 / 探索 0.6）、top_p 0.9、repetition_penalty 1.2、min_p 0.05、seed 42。
- **双阶段剖面**：探索（ToT 多方案）与验证（引用核查）明确区分，避免逻辑冲突。
- **证据分级**：症状原文(C) < 相似病例/病史(B) < 知识库指南/检查报告(A)；置信度必须匹配证据等级。
- **撤回兜底**：找不到支撑性引用即撤回该主张。
- **未知兜底**：多次验证无法确定 → 返回「我不知道/建议进一步检查」。
- **医生确认门控**：所有输出标注【待医生确认】。

### 7.1 后端插件化
- `core/plugin_manager.py`：`Plugin` 基类（生命周期钩子）+ `PluginManager` 注册表。

### 7.2 配置驱动的诊断工作流
- `services/diagnosis_workflow.py`：节点自注册 + `run_pipeline()`。
- 节点：`rule_engine` / `similar_cases` / `knowledge_base` / `patient_history` / `anti_hallucination_verify`。
- `diagnosis.diagnose()` 转交 `run_pipeline()`，输出结构不变。
- 编排：`config/agent_config.json → diagnosis_workflow.pipeline`；`GET/POST /api/ai/workflow`（写入 `data/workflow_override.json`）。

### 7.3 前端 Schema 驱动区块
- `blocks/`：`types.ts` + `registry.tsx` + `BlockRenderer.tsx`。
- 区块：`header` / `stat_card` / `workflow` / `plugins` / `agent_config`。
- `pages/LowCodeStudio.tsx`：只写一份 `schema` 即渲染页面（低代码工作台）。

### 7.4 员工域低代码引擎（2026-09-08 新增）
把 NocoBase 剩余三大能力移植到**员工域**（employee.db），全部真实落库、端到端可运行。详见 `docs/开发文档/员工域低代码设计方案.md`。

|---|---|---|
| 动态数据集合 | `models/workspace.py` + `services/dyn_engine.py` + `api/dyn.py` | 集合元数据 `dyn_collections`；创建集合时**物理建表 `dyn_<name>`**；通用 CRUD/搜索/分页自动可用 |

- 关键实现：`services/system_coll.py`（PRAGMA 白名单 + 原生 SQL，避免跨库外键反射问题）。

## 十、AI 模型训练详解

```
步骤1: 确定问题 → 步骤2: 准备数据 → 步骤3: 选择算法 → 步骤4: 训练验证 → 步骤5: 部署上线
```
- **问题类型**：图像二分类(CNN)、多分类(CNN/Transformer)、文本分类(Transformer)、语义搜索(向量+FAISS)、异常检测(无监督)。
- **数据准备**：原始 → 去噪清洗 → 标准化 → 增强 → 80/20 拆分。
- **算法**：CNN(影像)、Transformer(病历)、随机森林/SVM/XGBoost(结构化)、KNN(相似病例)。
- **验证**：十折交叉验证；超参数(learning_rate/batch_size/epochs/dropout)；指标 准确率/精确率/召回率/F1（**医疗重召回率**）。
- **部署**：云端训练 → ONNX → TensorRT → Docker → 部署到 Jetson。

**API Key 接入**：OpenAI(GPT-4o)、DeepSeek(deepseek-chat)、通义千问(qwen-max)、Claude(claude-sonnet-4)。全部可在「系统设置 → AI 服务商配置」填入。

## 十一、向量搜索与 RAG

- **向量**：把语句转成浮点数组，语义相近 → 距离近。
- **向量搜索**：`"头疼"→ "偏头痛/头部不适/太阳穴胀痛"`，比 SQL LIKE 更智能。
- **RAG**：先向量检索相似病例/知识库 → 作为引用资料喂给大模型 → 回答有据可查（配合防幻觉机制使用）。

## 十二、用户记忆系统

- **短期记忆**（当前会话）：浏览页面、搜索关键词、查看记录 → 内存缓存。
- **长期记忆**（跨会话）：主题/排序偏好、搜索历史、常用页面、活跃时段 → 归档数据库。
- **个性化推荐**：医生常搜“高血压”→ 控制台优先展示；运维关注 GPU 温度 → 推送设备异常。

## 十六、如何扩展（速查）

1. **新增后端模块** → 加 `api/<name>.py`，在 `core/plugins.py` 注册为插件。
2. **新增诊断节点** → `diagnosis_workflow.py` 写 `_stage_xxx` + `register_stage` + 配置登记。
3. **新增前端区块** → `blocks/registry.tsx` 注册，schema 引用。
4. **调整防幻觉参数** → 改 `config/agent_config.json` 的 `generation_parameters` / `scenario_parameter_profiles`。
5. **调整诊断流程** → 低代码工作台 或 `POST /api/ai/workflow`。
6. **员工端新增一张业务表（不写代码）** → 低代码工作台「数据源」创建集合（自动物理建表 + CRUD 页面）→ 「页面」创建页面 → 「权限」配置角色可见性；需要审批的在「工作流」创建触发集合=集合名的流程。
7. **修改员工端页面** → `page_schemas` / `/lcp/:pageKey`（区块配置驱动），无需改前端组件。

## 十七、技术术语小词典

| 术语 | 含义 | 用在哪 |
|------|------|-------|
| FastAPI | Python Web 框架，自动生成 API 文档 | 后端 |
| ORM | 用 Python 类操作数据库 | SQLAlchemy |
| JWT | 加密令牌，识别身份 | 登录 |
| Docker | 软件打包集装箱，跨平台 | 部署 |
| FAISS | 向量相似度搜索库 | 相似病例 |
| 向量 | 语句转数字串，代表语义 | AI 搜索 |
| RAG | 先检索再让 AI 回答 | 防幻觉增强 |
| ONNX/TensorRT | 通用模型格式/GPU 加速 | 边缘部署 |
| CoT/ToT | 思维链/思维树 | 诊断推理 |
| 十折交叉验证 | 数据分 10 份轮流验证取平均 | 模型训练 |
| 超参数 | 训练前手动的配置 | 模型调优 |

> 涉及医疗诊断，**所有 AI 建议仅供参考，最终诊断必须由执业医师确认。**

## 十八、技术栈与实现（汇总，详见 docs/开发文档/技术栈与实现.md）

| 层 | 技术 |
|----|------|
| 后端 | Python 3.11 + FastAPI + SQLAlchemy 2.0 + Pydantic v2 |
| 数据库 | SQLite(开发)/PostgreSQL(生产) + MongoDB(可选) + FAISS |
| 前端 | React 18 + TypeScript + Vite + Ant Design 5（Material3 / NocoBase 主题） |
| 认证 | JWT + 角色权限；刷卡/证件自动登录 `POST /api/auth/card-login` |
| AI | 混合：规则引擎 + 相似病例 + 知识库 RAG + 可选云端（OpenAI/DeepSeek/千问/Claude）+ 防幻觉 |

**关键模块**：插件化（`core/plugins.py`）、配置驱动诊断工作流（`diagnosis_workflow.py`）、员工消息（`message.py`）、通知（`notification.py`）、预约挂号（`appointment.py`）、患者注册（`patient_account.py`）、审计日志（`audit.py`）、Token 记账（`token_usage.py`）、上级查看下级脱敏记录（`/api/records/senior`）。

> ⚠️ 前端约定：项目开启 `verbatimModuleSyntax`，**类型必须用 `import type`**（最常见白屏原因）。

## 十九、数据库（双库，表结构 SQL 在 `db/` 目录）

- **患者数据库**：`db/患者数据库.sql`（patients / patient_accounts / appointments / medical_records / knowledge_docs / record_comments / doctor_schedules）。
- **员工数据库**：`db/员工数据库.sql`（users / messages / notifications / audit_logs / token_usage / conversations / dyn_collections 等低代码元数据表）。
- 当前运行时为**单库体系**：患者域 `backend/data/patient.db`、员工域 `backend/data/employee.db`（`create_all` + `_ensure_columns` 迁移）；上表为“患者域 / 员工域”逻辑拆分，可据此物理拆分。
- 字段说明见各表注释；敏感字段（证件号）为预留加密列。
