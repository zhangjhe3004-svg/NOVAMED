# MediCode 全域智慧医疗系统 · 使用教程

> 版本：v1.0（含 AI 防幻觉体系 + NocoBase 风格低代码增强）
> 适用对象：医生 / 药师 / 管理员 / 运维
> 配套技术文档见 `docs/开发文档/技术文档.md`

---

## 一、系统简介

MediCode是一个运行在本地边缘设备上的智慧医疗辅助系统，自带 AI 辅助诊断、患者管理、就诊记录、知识库、用户记忆等模块。

本版本在原有功能基础上做了三个重要增强：

1. **AI 防幻觉体系** —— 每条诊断都需要有证据支撑，找不到依据的主张会被撤回，证据不足时会明确告知用户。
2. **配置驱动的诊断工作流** —— 诊断的每个环节都可以开关、调整顺序，通过配置文件灵活编排。
3. **Noco风格低代码增强** —— 后端服务模块插件化、前端页面由 Schema 区块驱动构建。

## 二、快速启动

### 2.1 前置条件
- Python 3.11+
- Node.js 20+
- Git

### 2.2 一键启动（推荐）

项目根目录下的 `bat` 文件夹里已精简为 4 个脚本，**双击即可**：

| 双击 | 作用 |
|------|------|
| `bat\一键安装.bat` | 首次运行：装后端 Python 依赖 + 前端 Node 依赖 |
| `bat\一键启动.bat` | 一键弹三个窗口，同时启动后端 + 员工端 + 患者端；端口冲突时自动提示一键换端口 |
| `bat\初始化数据库.bat` | 重建患者库 / 员工库（会清空现有数据，谨慎） |
| `bat\端口工具.bat` | 检查端口 / 一键换端口（也可在启动时选择） |

**首次**：双击 `bat\一键安装.bat`，等装完。
**日常**：双击 `bat\一键启动.bat` → 弹出「后端」「员工端」「患者端」三个窗口 → 员工端浏览器开 http://localhost:3051 ，用 `admin / admin` 登录；患者端开 http://localhost:3052。
**停止**：关闭对应窗口即可。

> 若控制台中文提示乱码，不影响功能；脚本已设置 `chcp 65001`（UTF-8）。若后端启动报「WinError 10013 / 端口被占用」，在一键启动时选「一键换端口」，或运行 `bat\端口工具.bat`。

### 2.3 启动后端（手动）
```bash
cd backend
pip install -r requirements.txt          # 首次
uvicorn app.main:app --reload --host 127.0.0.1 --port 18001
```
启动日志会显示「已加载 N 个插件」。接口文档：http://localhost:18001/docs

**数据库初始化**（如需重置数据库）：
```bash
python scripts/init_databases.py
```

### 2.4 启动前端（手动）
```bash
cd frontend
npm install                              # 首次
npm run dev                              # 员工端 3051
npm run dev:patient                      # 患者端 3052
```
浏览器打开 http://localhost:3051（员工端） / http://localhost:3052（患者端）

### 2.5 登录
默认账号：**admin / admin**（管理员）

## 四、配置 AI 服务商（可选，用于云端深度分析）

> 不配置也能用：默认走**本地验证引擎**，完全离线、隐私最好。要"思维链 CoT 深度分析"才需要。

1. 进入 **系统设置 → AI 服务商配置**。
2. 选择服务商，粘贴 API Key，点 **保存**。支持：**OpenAI / DeepSeek / 通义千问 / Claude**。
3. Key 安全存储在服务器端 `backend/.env`。
4. 保存后，「AI 服务商状态」会显示已配置项；AI 诊断页的"分析引擎"下拉框也会出现云端选项。

> 断网或 Key 失效时，系统自动回退到本地验证引擎，不会崩溃。

## 五、使用 AI 辅助诊断（本地验证引擎，默认）

1. 打开 **AI 辅助诊断**（`/ai-assistant`）。
2. 可选：关联患者（带入既往病史，增强分析）。
3. 分析引擎保持 **本地验证引擎（离线防幻觉）**。
4. 输入症状，例如：`患者头痛3天，右侧太阳穴搏动性疼痛，伴恶心、畏光`。
5. 点 **开始 AI 分析**。

### 结果里重点看这几块（防幻觉）
- **每条诊断卡片**多出：**证据等级 A/B/C**、**风险等级**、**待医生确认**（紫色标签）、**引用证据定位**（这条诊断凭什么下结论）。
- **底部「防幻觉验证摘要」卡**：`证据校验通过 / 证据不足`、**已撤回的主张**（如果某候选诊断找不到引用，会被列在这里）、已启用的防幻觉机制。

### 怎么读"引用证据定位"
```
[症状原文] "患者头痛3天，右侧太阳穴搏动性疼痛，伴恶心、畏光" 命中典型症状：头痛、恶心、畏光
[患者病史] "患者有类似诊断史"
[相似病例] [病例#12] 诊断：偏头痛
[知识库]   《偏头痛诊疗指南》— ...
```
依据越多、越权威 → 证据等级越高（C < B < A）→ 置信度越高。

## 六、使用云端 CoT 深度分析（可选）

1. 确保已配置至少一家服务商（见第四节）。
2. 在 **分析引擎** 选择 `云端 OpenAI（CoT）` 或 `云端 自动选择`。
3. 输入症状，点 **开始 AI 分析**。

这次会调用外部大模型，用 **低温 0.2 + 防幻觉提示词** 做一次**思维链（CoT）鉴别诊断**：
- 结果里多出一张 **「AI 深度分析（思维链 CoT）」** 卡片，展示逐步推理。
- 其余防幻觉字段（证据等级、引用、撤回、待医生确认）依然保留。
- 云端失败会**自动回退本地**。

## 七、结果字段速查

| 字段 | 含义 |
|------|------|
| `engine` | 本次引擎：如 `workflow:rule_engine+similar_cases+...` 或 `cloud_cot` |
| `diagnoses[].evidence_tier` | 证据等级 A/B/C |
| `diagnoses[].citations` | 引用证据定位 `[{source, quote}]` |
| `diagnoses[].confirmation_required` | 是否需医生确认（恒为 true） |
| `verification.verification_status` | `confirmed`（通过）/ `uncertain`（不足） |
| `verification.retracted_claims` | 被撤回的主张 |
| `verification.unknown_fallback` | 「我不知道/建议进一步检查」 |
| `ai_analysis` | 云端 CoT 分析文本（仅云端路径） |

## 八、低代码工作台（管理员）

入口：左侧菜单 → 管理员 → **低代码工作台**（`/lowcode`）。页面由 Schema 区块驱动，可做三件事：

1. **诊断工作流节点**：开关 / 上下调整排序（规则引擎、相似病例、知识库、患者病史、防幻觉验证）。改动**立即生效**。
   - 快速验证：关掉「规则引擎」→ 去 AI 诊断页跑一次 → 结果变成「我不知道/建议进一步检查」，说明工作流确实按配置执行。
2. **插件市场**：启停后端插件（认证、用户、患者、记录、AI、记忆、知识库、AI服务商）。**重启后生效**。
3. **AI 防幻觉配置**：查看角色、生成参数、证据分级。

## 十、常见问题 FAQ

**Q1：某个可能的诊断不见了？**
被防幻觉层"撤回"了（找不到支撑性引用）。见底部「已撤回的主张」。

**Q2：为什么返回「我不知道 / 建议进一步检查」？**
症状证据不足，无法可靠诊断。这是防幻觉机制在起作用，不是系统坏了。按提示补充检查后复诊。

**Q3：选了云端却还是本地结果？**
原因：未配置该服务商 Key / 调用失败（断网、额度）/ 已自动回退本地。

**Q4：置信度比之前低？**
正常。防幻觉层按证据等级校准：仅症状原文支持（C 级）的诊断置信度被压低（≤0.55）。

**Q5：插件启停为什么没立即生效？**
插件在**下次启动**时加载（与 NocoBase 一致）。工作流节点是**立即生效**。

**Q6：在哪看当前防幻觉配置与工作流？**
系统设置 → AI 防幻觉配置；低代码工作台 → 诊断工作流。

## 十一、接口速查

| 接口 | 用途 |
|------|------|
| `POST /api/ai/diagnose` | 本地验证引擎（含防幻觉验证） |
| `POST /api/ai/analyze` | 云端 CoT 深度分析，失败自动回退本地 |
| `GET /api/ai/config` | 查看 AI 防幻觉配置 |
| `GET/POST /api/ai/workflow` | 查看/更新诊断工作流 |
| `GET /api/ai/providers` | 已配置的云端服务商 |
| `GET /api/ai-keys` | API Key 配置状态（脱敏） |
| `GET /api/plugins` | 插件列表 |
| `POST /api/plugins/{name}/enable|disable` | 启停插件（管理员） |

> 涉及医疗诊断，请务必牢记：**所有 AI 建议仅供参考，最终诊断必须由执业医师确认。**
